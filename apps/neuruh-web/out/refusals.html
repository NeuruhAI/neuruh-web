Architecture, not results

Each capability below is real as design and code, demoable as architecture, and never sold as a running outcome. The gate that would move it to a result is published next to it.

Self-improvement / the learning loop

Exists in code with passing tests and has never executed on a real outcome. The calibration ledger refuses entries that arrive without a pre-registered outcome; the honest result of the first real run was DEFERRED_BY_CONTRACT.

Gate to a result: One real decision producing a real, attributed outcome — then 30 samples before any claim.

Automatic production promotion

Classification runs in shadow; nothing is written to production automatically.

Gate to a result: Founder adoption of the graduation contract for the production write path.

Private / on-prem deployment

The architecture supports it. It has never been deployed for anyone.

Gate to a result: A customer environment and a delivered deployment.

Outreach — dialing, SMS, email

Surfaces exist. Nothing we built has ever contacted a person.

Gate to a result: Contact enrichment, a compliance stack, and explicit founder authorization.

A second production vertical

Named and tested against a published five-condition framework. Not opened.

Gate to a result: At least 20 attributed outcomes from at least 2 customers in the first vertical.

Outcome-based or success-fee pricing

Modelled. Not offered.

Gate to a result: The same 20 attributed outcomes.

Why publish this

Most systems record what they did. Neuruh also records what it declined to do, and why — an authority gate that withholds an action writes a receipt just like one that permits it. This page is the same discipline applied to marketing: the claims we refuse to make, kept as visible as the ones we make.

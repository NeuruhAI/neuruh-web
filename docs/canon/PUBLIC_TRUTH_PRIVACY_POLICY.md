# Public Truth Privacy Policy

Posture: read-only, deny by default, allowlisted projection only.

## Allowed

- Founder-approved public terminology, summaries, route identifiers, and claim boundaries.
- Dated public-safe object/event state with explicit truth mode and source metadata.
- Curated relationships, public research records, selected receipts, and classified metrics.
- Repository-relative source identifiers that do not expose a private machine location.

## Forbidden

- Secrets, credentials, tokens, keys, passwords, or environment values.
- Absolute/local paths, private archive contents, raw personal memory, customer/tenant data,
  personal sensitive data, defense details, private IP internals, or unpublished legal records.
- Unreviewed claims, remembered counts presented as current, or internal operational identifiers
  that create a false production-state impression.
- Public write capability or direct reads from arbitrary private systems.

## Compiler enforcement

Known forbidden keys are recursively stripped and recorded as redactions. Unknown fields,
residual private-value patterns, unresolved source references, missing truth metadata, stale
snapshots, and unclassified numeric leaves fail compilation. Output schemas disallow
additional properties.

Raw canon remains repository intake and is not served by the application. Public routes expose
only the compiled allowlist. A source metadata record marked `public_safe` means its public
reference metadata is approved; it does not publish the underlying private working document.

## Future connectors

No connector exists in P1. A future connector must compile out-of-process, use least privilege,
emit the same allowlisted contract, preserve append-only receipts, and pass privacy/source/
freshness review before replacing the checked-in snapshot.
